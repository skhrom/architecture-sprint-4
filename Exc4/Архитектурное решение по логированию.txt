В идеале внедрить логирование для каждого сервиса, но в данный момент это невозможно.
Поэтому как минимум нужно внедрить для сервисов:
MES
MES API
3D FILE STORAGE
CRM API
Messages Queue (по идее, пишутся автоматически)
MES db (логи на уровне БД, по идее пишутся всегда по умолчанию)

Список логов, с уровнем INFO
Система начала расчет стоимости заказа (id заказа, id пользователя, время)
Система закончила расчет стоимости заказа (id заказа, id пользователя, время)
Изменение статуса заказа (id заказа, id пользователя, новый статус, время)
Запрос информации о заказах (id пользователя, время, фильтры(если есть))
Логирование запросов, которые делают Sellers (id пользователя, время, информация о запросе)

Другие уровни логирования
DEBUG - только для отладки в дев-среде, если локально протестировать невозможно.
    По возможности удалять после отладки, чтобы не засорять код
    и не тратить вычислительные ресурсы для формирования сообщения.

WARNING - незапланированные события, но которые не ломают систему.
    Например, пользователь второй раз хочет рассчитать стоимость одной и той же модели
    или какой-то пользователь сделал очень много запросов и т.п.

ERROR - ошибки системы, которые не должны возникать в идеальном мире.
    Например, timeout, при обращении к другому сервису или системная ошибка уровня NullPointerException и т.п.

Мотивация
- позволит быстрее выявлять ошибки
- позволит вести бизнес-логи, и на основании их вести например статистику, сколько заказов в день создано

На какие метрики повлияет:
- среднее время отклика, так как будут выявлены места, где системы падает с ошибкой
- количество ошибок, так как логирование быстрее позволит выявить ошибки, а значит и их количество уменьшится
- позволит выявить проблемные участки кода, где коды долго выполняется
- снижение времени отклика для операторов (бизнес метрика)
- удовлетворенность пользователей (бизнес метрика)

Предлагаемое решение
- использование ELK стека
    - в приложениях используются наиболее известные библиотеки для логирования
    - логирование в БД и Rabbit настраивается в конфигурационных файлах
    - filebeat устанавливается на каждом сервере для сбора логов, отправляет логи в logstash
    - logstash отправляет в elasticsearch
    - kibana используется для визуализации логов

- чувствительные данные (персональная, финансовая информация и т.п) в логи не должны попадать,
  но если важно в логах зафиксировать, что информация получена, то тогда эти данные должны маскироваться.

- для каждой системы заводится свой индекс, где префикс в названии - это имя системы (например, MES_API).
  Время хранения и размер логов зависит от доступных ресурсов.
  На первом этапе размер логов по каждому индексу не должен превышать 10 ГБ, а срок хранения 1 месяц.

Превращение системы сбора логов в систему анализа логов.
Предлагается настроить алертинг. Уведомления отправляются девопсам или Продакт-менеджеру
Типы алертов:
- DDoS-атака
- количество 500-х превысило 100 за 1 минуту, можно разбить по группам (500, 502 и т.д.)
- количество ошибок в сервисе резко выросло
- и т.п.
