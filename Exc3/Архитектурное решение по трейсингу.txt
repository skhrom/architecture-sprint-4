Покрыть трейсингом сервисы:
MES
MES API
3D FILE STORAGE
CRM API
Messages Queue

Список данных для трейсинга:
Статические: имя сервиса, ip-ноды (или имя ноды, где запущен сервис)
Динамические:
    - идентификатор запроса
    - возможно тело запроса для некоторых методов

Мотивация:
- более быстрая локализация проблемы, так как быстрее можно понять, где завис запрос

На какие метрики повлияет:
- среднее время отклика, так как будут выявлены узкие места в обработке запросов
- количество ошибок, так как трейсинг быстрее позволит выявить ошибки, а значит и их количество уменьшится
- снижение времени отклика для операторов (бизнес метрика)
- удовлетворенность пользователей (бизнес метрика)


Предлагаемое решение:
Схема с использованием Jaeger доступна по ссылке ниже:
https://drive.google.com/file/d/1tFbelF9XxkzJpCqN4xt0FYSQQHdKZOBm/view?usp=sharing

1) Развернуть Jaeger и Jaeger UI
2) В сервисы, где нужен трейсинг, внедрить и настроить OpenTelemetry
3) Если целевое решение смотреть метрики, трейсы через графану, то добавить в графану
   (предполагается, что она уже установлена) плагин Jaeger

Компромиссы:
1) В сервисы, в которых не наблюдается существенных проблем (Internet Shop, Shop API, CRM),
   пока можно не добавлять трейсинг, так как настройка Open Telemetry повлечет за собой дополнительные расходы
   на разработку и тестирование.

2) Если текущие проблемы решаются просто добавлением большего количества инстансов, то трейсинг можно добавить
   после контейнеризации системы (когда все сервисы разворачиваются в контейнерах, а не на виртуалках), так как
   конфигурацию приложений все равно придется подстраивать под деплой в k8s

Аспекты безопасности:
- Доступ к трейсингу доступен только во внутренней сети
- Доступ к просмотру трейсов доступен только внутренним пользователям с определенной ролями
  ("Тестировщик", "Разработчик", "DevOps-инженер", "Поддержка")
- Настройка Jaeger доступна только DevOps-инженерам
