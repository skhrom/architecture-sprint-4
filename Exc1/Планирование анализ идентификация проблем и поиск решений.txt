Существующие и потенциальные проблемные места
- каждое приложение имеет по одному экземпляру
- каждое приложение разворачивается на виртуалке
- один инстанс БД для записи и чтения
- MES API и сам сервис расчета стоимости. Сервис расчета и так не быстрый и грузит приложение скорее всего,
  еще добавились и внешние вызовы через API
- MES для операторов вызывает MES API, который может быть загружен расчетом стоимости заказа

Инициативы для устранения нежелательных ситуаций
- увеличить количество инстансов MES API (чтобы снизить нагрузку на сервис)
- добавить реплики для БД и реализовать чтение сначала из реплик (так как это наиболее часто выполняемые операции)
- в сервис MES добавить circuit breaker, для того чтобы не ддосить сервис MES API, который и так загружен

- между сервисами MES API и MES реализовать BackPressure (MES API сообщает о своей загруженности)
- разбить сервис MES API на два микро сервиса (первый выполняет расчет стоимости производства изделия, второй принимает запросы от пользователя MES API)
- увеличить количество инстансов каждого из приложений (чтобы снизить нагрузку на сервисы)
- добавить кэширование запросов для пользователей (информация меняется не очень часто для них)
- добавить мониторинг
- проанализировать, какие логи есть, достаточно ли их, если нет, то добавить нужные логи
- в будущем добавить трейсинг, чтобы точно отслеживать, где зависает запрос
- внедрить контейнеризацию и перевести развертывания приложений в k8s
- для поддержки контейнеризации нужны будут еще DevOps-инженеры (1,2)
